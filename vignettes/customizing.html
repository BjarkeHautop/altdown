Customizing your site

Source: vignettes/customizing.qmd

If you want to customize your site, you can do so by editing _quartodown.yml at the package root, which quartodown::use_quartodown() creates. It has five fields, all optional:

  • url: is the site’s address, if it isn’t the first non-GitHub URL in DESCRIPTION.
  • reference: groups and orders the function reference index.
  • navbar: lays out the navbar.
  • home: picks the home page’s source.
  • quarto: changes any other Quarto setting.

The reference index

Without reference:, the index lists every function in one section. To group them, list the sections:

reference:
  - title: Read and write
    desc: Functions for getting data in and out.
    contents:
      - read_data
      - starts_with("write_")
  - title: Helpers
    subtitle: Low-level
    contents:
      - has_concept("helpers")
      - -internal_helper
1
Each entry becomes a section of the index, with this heading.
2
Optional Markdown text, shown under the heading.
3
A topic, by any of its \alias{} names or its Rd file name.
4
A selector.
5
An optional heading one level below title.
6
A leading - removes a topic.

The selectors are:

Selector Selects topics
starts_with("x"), ends_with("x"), contains("x") with an alias that starts with, ends with or contains x
matches("regex") with an alias matching a regular expression
has_concept("x"), has_keyword("x") with that \concept{} or \keyword{}
c(...) selected by any of the selectors given
- before a topic or selector removed from those the entries above select, or as the first entry, from all topics

Topics that no section lists get a warning and are left off the index. The exception is \keyword{internal} topics, which are left out, without a page, unless named, as with roxygen’s reexports, or selected with internal = TRUE, as in starts_with("dev_", internal = TRUE).

The format is the same as pkgdown’s reference: field, so an existing one can be copied over.

The navbar

navbar: lists the items on the navbar’s left and right, in order. The default is:

navbar:
  left: [intro, reference, articles, news]
  right: [github]

Each of these is a keyword that quartodown turns into an item, and leaves out if the package has nothing for it:

Keyword Item
intro “Get started”: the vignette named after the package, or the only top-level vignette if there’s just one
reference “Reference”: the function reference index
articles “Articles”: a menu of every vignette no other item links, top-level ones first, then those in subfolders
news “Changelog”: NEWS.md
github A GitHub icon linking the repository in DESCRIPTION’s URL

Any other item is a vignette, given as its path relative to vignettes/ without extension and linked with its title, or a Quarto navbar item. Inside a Quarto item’s menu:, vignettes are given the same way, and a folder ending in / lists every vignette in it.

For example, with the vignettes in a folder for each menu:

navbar:
  left:
    - reference
    - news
    - text: Get started
      menu:
        - get-started/installation
        - get-started/first-steps
    - text: User guide
      menu: user-guide/
    - text: Developers
      menu:
        - dev/internals
        - text: Contributing
          href: CONTRIBUTING.md
  right:
    - text: Blog
      href: https://example.com/blog
    - github
1
vignettes/get-started/installation.qmd.
2
Every vignette in vignettes/user-guide/, sorted by file name.
3
Any Quarto navbar item works in a menu too.

Vignettes can live in any subfolder of vignettes/. Files and folders whose name starts with _ or . are skipped, as Quarto does.

Every vignette is built, even one the navbar doesn’t link to. Such a vignette can only be reached through links from other pages, so build_site() warns about it, unless the navbar has articles, which lists every vignette nothing else links.

Note

R only builds top-level vignettes into the package, so vignettes in subfolders are website-only.

The home page

The home page shows README.md, or, if there is none, the package’s description from DESCRIPTION. To give the site a different home page than the README, use home: file: at another file, relative to the package root:

home:
  file: index.qmd

It can be Markdown (.md) or a Quarto document (.qmd), whose code runs when the site is built, as in a vignette. Write links and image paths in it relative to the package root, as in the README. Add the file to .Rbuildignore so R CMD check doesn’t complain.

Next to the page, a sidebar shows the package’s links, license, citation, authors and badges. For full control over the page, turn it off with sidebar: false:

home:
  file: index.qmd
  sidebar: false

The page then shows the file as written. Like any other page, it then gets a table of contents, which toc: false in its front matter can turn off.

Other Quarto settings

quartodown writes a Quarto configuration into _quarto/_quarto.yml (overwritten on every build). The quarto: field is merged over it, key by key:

  • A list of entries, such as website: navbar: left:, is added to.
  • Any other value is replaced.
  • ~ removes a setting.

For example, to fold code blocks, drop the table of contents and change the footer:

quarto:
  format:
    html:
      code-fold: true
      toc: ~
  website:
    page-footer:
      right: "Built with love."

See the Quarto website reference for the full list of changes you can make.

quarto: applies to every page. To change a single vignette instead, set the option in its front matter, which overrides the site-wide value:

---
title: "A long tutorial"
format:
  html:
    code-fold: true
    toc-depth: 3
---

To change a single code chunk, use a chunk option such as #| code-fold: true.

Coming from pkgdown

Moving a site over is very easy, and mostly means moving _pkgdown.yml’s settings into _quartodown.yml:

  • reference: has the same format and selectors, so it can be copied as is.
  • navbar: lists items differently; see The navbar.
  • template: (Bootstrap version, bslib variables, theme) has no equivalent: style the site with Quarto’s theme: under quarto: format: html:, as in Other Quarto settings.
  • articles: has no equivalent: group vignettes with navbar menus instead.
  • A separate home page (an index.md used instead of the README) isn’t picked up automatically: set it with home: file:.
  • Code that checks IN_PKGDOWN (or pkgdown::in_pkgdown()) should check identical(Sys.getenv("IN_QUARTODOWN"), "true") instead.

The rest works as with pkgdown, except that vignettes are published under vignettes/ rather than articles/: articles/foo.html becomes vignettes/foo.html, and articles/bar.html, from vignettes/articles/bar.Rmd, becomes vignettes/articles/bar.html, so update any links pointing to them.
