Technical details

Source: vignettes/articles/technical.qmd

quartodown generates a Quarto website project from the package sources, so the man pages, vignettes and generated pages are all Quarto pages, and every Quarto feature works.

How a build works

quartodown::build_site() runs in three stages:

  1. Before rendering, it installs the package into a temporary library and writes a Quarto project into _quarto/.
  2. During rendering, Quarto renders _quarto/ into docs/, running the examples and vignettes against that package.
  3. After rendering, it links code to its documentation and adds hover tooltips.

In an interactive session it then serves docs/ with preview_site(). The server keeps running for the rest of the session, so after a rebuild the open page reloads instead of a new one opening.

build_site(devel = TRUE) skips the install and loads the package from source with pkgload::load_all() instead. It is faster, but code that starts other R processes (for example with callr or parallel) won’t find the package, and build-stage \Sexpr{} macros in the man pages don’t run.

Throughout the build, the environment variable IN_QUARTODOWN is "true", so the package’s code can tell it is running for the site, and IN_QUARTODOWN_PKG is the package’s name.

_quarto/ is rewritten on every build, and gitignored by quartodown::use_quartodown(). To change the site, edit _quartodown.yml instead (see Customizing your site).

_quarto/
├── _quarto.yml                   # Quarto configuration (navbar, footer, theme)
├── index.qmd                     # home page
├── reference/
│   ├── index.qmd                 # function reference index
│   └── <topic>.qmd               # a page per man/*.Rd
├── authors.qmd                   # authors and citation page
├── vignettes/                    # the vignettes, as they are
├── man/figures/                  # images for the README and man pages
├── NEWS.md                       # changelog, with issues and users linked
└── quartodown.scss               # theme on top of Quarto's HTML

The man pages

Each man/*.Rd file becomes a reference page, served at reference/<topic>.html. It is rendered with the package’s Rd macros (such as Rdpack’s \insertRef{}), and build-stage \Sexpr{} macros run with the package installed, as in R CMD build. Examples run, with their output in the same block as the code, prefixed with #>. To give a chunk’s output a block of its own, in a vignette too, set #| collapse: false on it.

If DESCRIPTION’s URL includes a GitHub repository, each reference page and vignette links to its source file under the title.

Code links and tooltips

downlit links function calls in R code blocks, and inline code like mean(), to their documentation. docs/pkgdown.yml lets downlit on other sites link to your reference pages in turn.

References to the package’s own functions also get a hover tooltip with their usage and the first sentence of their description. build_site() warns when a first sentence is longer than 200 characters, since the tooltip cuts it off. To build without tooltips, use build_site(tooltips = FALSE).

The theme

The site uses Quarto’s default theme in light mode and darkly in dark mode, with quartodown.scss on top of each. The mode follows the browser’s preference.

Code output keeps the colors packages such as cli give it in a terminal, in shades that suit the light or dark theme.

preview_site(path = ".")Serves docs/, as built by build_site(), in a web browser, and reloads the page when the site is rebuilt.
