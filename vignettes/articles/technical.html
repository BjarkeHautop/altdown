Technical details

altdown doesn’t render anything itself: altdoc converts the man pages and vignettes and renders them with Quarto, and altdown supplies the pkgdown-style layout around them.

How a build works

altdown::build_site() runs in three stages:

  1. Before rendering, it writes a set of files into altdoc/, which altdoc copies into its Quarto project. This is the approach altdoc recommends for customizing Quarto sites.
  2. During rendering, altdoc::render_docs() converts the Rd files to Quarto pages and renders the project, with a pre-render script fixing up the man pages.
  3. After rendering, it adds hover tooltips to the HTML in docs/.

The only file you edit is altdoc/altdown.yml. Everything else in altdoc/ is rewritten on every build, and gitignored by altdown::use_altdown():

altdoc/
├── altdown.yml                # configuration, edited by hand
├── quarto_website.yml         # Quarto configuration (navbar, footer, theme)
├── index.md                   # home page
├── reference.qmd              # function reference index
├── authors.qmd                # authors and citation page
├── altdown.scss               # pkgdown-style theme on top of Quarto's HTML
├── altdown-header.html        # dark-mode default
├── altdown-after-body.html    # navbar alignment
└── altdown-pre-render.R       # fixes up altdoc's man pages

Before rendering

The home page

altdoc/index.md replaces altdoc’s home page. It holds the README next to a pkgdown-style sidebar with links, the license, the citation, the developers and the README’s badges. On narrow screens the sidebar moves below the content.

A README <picture> with a light and a dark version (GitHub’s prefers-color-scheme convention) becomes one <img> per theme, switched by the site’s light/dark toggle.

The reference index

altdoc can’t group and order the function index (etiennebacher/altdoc#326), so altdoc/altdown.yml has a reference: field in the same shape as pkgdown’s:

reference:
1  - title: Building the site
2    desc: >
      Set up a package, then build its site.
    contents:
3      - use_altdown
4      - starts_with("build_")
1
Each entry becomes a section of the index, with this heading.
2
An optional description, shown under the heading.
3
A topic, by any of its \alias{} names.
4
A selector, as in pkgdown: starts_with(), ends_with(), contains(), matches(), has_concept(), has_keyword(), - to exclude and c() to combine.

The navbar and footer

The navbar links the “Get started” vignette, the reference index, the other vignettes under “Articles” and the changelog. The footer has pkgdown’s “Developed by …” text, built from Authors@R.

TipChanging the Quarto configuration

A quarto: field in altdown.yml is merged over the generated configuration. Lists, like the navbar’s items, are appended to; any other setting is replaced, and ~ removes it. For example, to add a navbar link and fold code blocks:

quarto:
  website:
    navbar:
      right:
        - text: Blog
          href: https://example.com
  format:
    html:
      code-fold: true

During rendering: the man pages

altdoc converts man/*.Rd to .qmd and renders straight after, so build_site() can’t edit those pages beforehand. Instead, altdown-pre-render.R runs as a Quarto pre-render script and makes them look like pkgdown’s:

  • Usage is a syntax-highlighted R code block with a copy button.
  • Inline code is rendered as Markdown code spans, so quotes and backslashes survive Pandoc.
  • Examples show their output in the same block, prefixed with #>, and the library() call for the package itself is hidden.
  • \dontrun{} examples become plain code blocks, so the page renders without starting an R session.

After rendering: hover tooltips

After rendering, build_site() links every reference to one of the package’s functions, in code blocks or inline code, to its man page. Hovering shows a tooltip with its usage and the first sentence of its description. Try it: hover over build_site() or use_altdown().

The sentence is cut off at 200 characters, and build_site() warns when one is longer. To build without tooltips, use build_site(tooltips = FALSE).

Matching the pkgdown look

altdown.scss is styled after pkgdown’s pkgdown.scss, written for Quarto’s HTML, and layered on top of Quarto’s own themes:

theme:
  light: [default, altdown.scss]
  dark: [darkly, altdown.scss]

darkly normally uses the Lato web font and larger headings, so text would reflow when toggling between light and dark. altdown.scss therefore sets Bootstrap’s system font stack and heading sizes for both themes.

Two things need JavaScript:

  • Dark mode by default. altdown-header.html starts new visitors on the dark theme if their system prefers it.
  • Aligning the navbar title with the body text. The body’s left edge differs between the home page and other pages, so altdown-after-body.html measures it and adjusts the navbar’s padding.
