Technical details

quartodown generates a Quarto website project from the package sources, so the man pages, vignettes and generated pages are all Quarto pages, and every Quarto feature works.

How a build works

quartodown::build_site() runs in three stages:

  1. Before rendering, it installs the package into a temporary library and writes a Quarto project into _quarto/. With build_site(devel = TRUE), each page’s R process loads it from source with pkgload::load_all() instead.1
  2. During rendering, Quarto renders _quarto/ into docs/, running the examples and vignette code against that package.
  3. After rendering, it links code to its documentation and adds hover tooltips.

The only file you edit is _quartodown.yml. _quarto/ is rewritten on every build, and gitignored by quartodown::use_quartodown():

_quarto/
├── _quarto.yml                   # Quarto configuration (navbar, footer, theme)
├── index.md                      # home page
├── reference/
│   ├── index.qmd                 # function reference index
│   └── <topic>.qmd               # a page per man/*.Rd
├── authors.qmd                   # authors and citation page
├── vignettes/                    # the vignettes, as they are
├── man/figures/                  # images for the README and man pages
├── NEWS.md                       # changelog, with issues and users linked
├── quartodown.scss               # theme on top of Quarto's HTML
├── quartodown-header.html        # dark-mode default
└── quartodown-after-body.html    # navbar alignment

Reference pages are served at reference/<topic>.html, and docs/pkgdown.yml lets downlit on other sites link to them.

Before rendering

The home page

index.md holds the README next to a sidebar with links, the license, the citation, the developers and the README’s badges.

A README <picture> with light and dark versions shows the one matching the site’s theme.

The reference index

To group and order the function index, use the reference: field in _quartodown.yml:

reference:
1  - title: Building the site
2    desc: >
      Set up a package, then build its site.
    contents:
3      - use_quartodown
4      - starts_with("build_")
1
Each entry becomes a section of the index, with this heading.
2
An optional description, shown under the heading.
3
A topic, by any of its \alias{} names.
4
A selector: starts_with(), ends_with(), contains(), matches(), has_concept(), has_keyword(), - to exclude and c() to combine.

build_site() warns about any topic the index leaves out, except \keyword{internal} ones. An internal topic is listed, and gets a page, only when named, as with roxygen’s reexports, or selected with internal = TRUE, as in starts_with("dev_", internal = TRUE).

The navbar and footer

The navbar links the “Get started” vignette, the reference index, the other vignettes under “Articles” and the changelog. The footer has a “Developed by …” line, built from Authors@R.

Code output

R output is shown in the same block as the code, prefixed with #>. To show a chunk’s output in a block of its own, set #| collapse: false on it.

TipChanging the Quarto configuration

A quarto: field in _quartodown.yml is merged over the generated configuration. Lists, like the navbar’s items, are appended to; any other setting is replaced, and ~ removes it. For example, to add a navbar link and fold code blocks:

quarto:
  website:
    navbar:
      right:
        - text: Blog
          href: https://example.com
  format:
    html:
      code-fold: true

The man pages

Each man/*.Rd file, except \keyword{internal} ones the reference index doesn’t list, becomes a reference page, rendered with the package’s Rd macros (such as Rdpack’s \insertRef{}). Build-stage \Sexpr{} macros run with the package installed, as in R CMD build, though not with devel = TRUE.

  • Usage, the usage of R6 methods, and code blocks with a language, such as roxygen’s ```yaml, are syntax-highlighted with a copy button.
  • Links go to the topic’s reference page, or, for another package’s topic, to its documentation as downlit finds it.
  • Math in \eqn{} and \deqn{} is rendered.
  • Examples run, with their output in the same block. \dontrun{} code is shown but not run, \dontshow{} code is run but not shown, and @examplesIf examples run only if their condition holds.

After rendering

downlit links function calls in R code blocks, and inline code like mean(), to their documentation. In blocks with code annotations, only function calls and %op% operators such as %in% are linked.

References to the package’s own functions also get a hover tooltip with their usage and the first sentence of their description. Try it: hover over build_site() or use_quartodown(). build_site() warns when a first sentence is longer than 200 characters, since the tooltip cuts it off. To build without tooltips, use build_site(tooltips = FALSE).

The theme

The site uses Quarto’s default theme in light mode and darkly in dark mode, with quartodown.scss on top of each:

theme:
  light: [default, quartodown.scss]
  dark: [darkly, quartodown.scss]

quartodown.scss gives both modes the same font and heading sizes, so switching modes doesn’t shift the text. quartodown-header.html and quartodown-after-body.html also:

  • show the dark theme to new visitors whose system is set to dark mode,
  • line up the navbar title with the page text,
  • show the version number smaller next to the package name,
  • leave #> output lines out when copying code.

Footnotes
